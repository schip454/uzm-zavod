# Сайт УЗМ

Сайт под брендом «Уральский завод металлоизделий» для ООО «Уральский завод металлоконструкций» на Next.js. Каталог включает металлоконструкции, опоры освещения, сваи, элементы трубопроводов, цоколи, кронштейны, светильники и антидроновую защиту.

## Локальный запуск

```bash
npm install
npm run dev
npm run typecheck
```

## Статическая версия для просмотра

```bash
npm run build:static
```

Готовые файлы лежат в `out`. На REG.RU для показа используется `uzm.spectrise.ru`; при обновлении загружается содержимое `out` в `www/uzm.spectrise.ru`. Команда создаёт `robots.txt` с запретом индексации тестового адреса. Публичная версия на REG.RU обновляется отдельно от локальной сборки.

На 19 октября 2026 года реестр содержит 30 разделов и 3 301 карточку: серии, группы изделий и отдельные модели. Характеристики есть у 3 262 карточек, изображения у 2 515, галереи из нескольких изображений у 1 921. Описание есть у 3 296 карточек; если поставщик публикует только поля, введение составлено из этих полей. Это не означает, что каждая карточка полностью укомплектована документацией: у части моделей источник сообщает лишь несколько параметров.

В 234 карточках есть таблицы исполнений. Их 2 898 строк включают ссылки на отдельные модели и уже существующие таблицы светильников, свай и опор трубопроводов. Строки таблиц пересекаются с отдельными карточками: складывать эти числа нельзя. Таблицы поддерживают поиск и переносят выбранную марку в заявку. В галереях работают миниатюры, стрелки и увеличение; в карточках доступны вкладки характеристик и описания. Анимация появления блоков отключается при системной настройке уменьшения движения.

Заявка формирует письмо на `zavod@uzmzavod.ru`; файл посетитель прикладывает в почтовом приложении. Прямая отправка и CRM зависят от серверного размещения и данных CRM.

## Каталог и источники

- `src/data/products.json` — товары из источников, присланных заказчиком.
- `src/data/dekart-full.json` — дополнительные названия серий из перечня «Декарта»; файл создаётся командой `python scripts/expand-dekart-inventory.py`.
- `src/data/catalog-content.ts` — структура групп и редакционные тексты.
- `src/data/verified-products.json` — сверенные параметры серий, таблицы исполнений и привязки изображений. Основной реестр дополняется этим файлом.
- `src/data/supplier-products.json` — отдельные модели «Декарта» из каталогов и пагинации.
- `src/data/additional-supplier-products.json` — модели «Точки опоры», ОМК и «СветПласта».
- `src/data/supplier-content.json` — перенесённые поля, описания, проверенные галереи и таблицы серий.
- `src/data/krasznam-products.json` и `krasznam-content.json` — опоры трубопроводов, трубы и фасонные изделия ППУ.
- `src/data/project-content.json` — редакционные уточнения проекта, которые сохраняются при повторном импорте.
- `public/images/sources/` — сверенные с сериями фотографии и исходные технические изображения из разрешённых каталогов без водяных знаков.
- `public/images/products/` — 531 уникальное проверенное изображение; один и тот же ракурс может использоваться в нескольких исполнениях, если так устроены карточки поставщика.
- `research/catalog-audit.csv` — построчная проверка источника, фотографии и характеристик. Обновление: `npm run audit:catalog`.
- `research/supplier-coverage.csv` — сверка найденных и перенесённых URL в согласованных разделах семи поставщиков. Это охват выбранных разделов, а не всех товаров каждого сайта.
- `research/published-product-images.json` — происхождение изображений с привязкой к модели и исходной странице.
- `research/Запрос_фото_без_водяных_знаков.csv` — обнаруженные изображения с водяными знаками. Часть карточек уже имеет другие чистые ракурсы.
- `research/Недостающие_фотографии.csv` — 786 карточек без чистого изображения.
- `research/Уточнить_характеристики.csv` — 39 карточек без полей и таблиц; сюда входят изделия по индивидуальному проекту и серии, для которых нужна документация.
- `research/pile-variant-sources.json` и `research/pile-image-sources.json` — происхождение обозначений и изображений свай.

Таблицы «Классик Электро» воспроизводятся из сохранённых страниц командой `python scripts/import-luminaire-tables.py`. Реестр свай ОМК собирается командой `python scripts/import-pile-variants.py`: она читает страницы каталога и все ссылки пагинации, которые есть в них. Сборка сайта не обращается к поставщикам.

Параметры 15 металлических опор ВЛ перенесены из полей карточек «Точки Опоры»; повторный импорт из сохранённых страниц — `python scripts/import-toenergo-properties.py`. Изображения этих опор пока не публикуются из-за водяных знаков.

Новый импорт выполняют `scripts/import-supplier-content.py`, `discover-other-suppliers.py` и `import-krasznam-content.py`. Для парсинга нужны BeautifulSoup и Pillow в локальном окружении Python. Изображения проходят ручной визуальный просмотр перед публикацией; решения записаны в `research/image-review-decisions.json`. `publish-supplier-content.py` публикует только одобренные файлы. `python scripts/verify-catalog.py` проверяет уникальность адресов, наличие файлов галерей, ссылки на серии и модели, затем обновляет списки недостающих материалов. Известные изображения с водяными знаками не скачиваются повторно и не публикуются.

Реестр включает модели из сторонних каталогов по запросу заказчика. Возможность изготовления и точные параметры исполнения УЗМ нужно сверить по чертежам или выгрузке 1С. На страницах нет заявлений о наличии товара. Ошибочные сгенерированные изображения удалены. Изображения светильников с водяными знаками и текстовыми наложениями исключены; чистые оригиналы ожидаются от заказчика. Фотографии объектов УЗМ взяты с действующего сайта. Материалы новой съёмки заменят снимки по мере поступления.

## Админка

В `cms` подготовлена локальная Payload CMS с коллекциями разделов, товаров, медиа, заявок и пользователей. Команда `npm run seed:catalog` внутри `cms` загружает каталог как черновики. Для размещения админки и автоматической отправки заявок потребуется сервер с Node.js, адрес CRM и данные обмена с 1С. Веб-сайт пока читает локальный реестр каталога, поэтому правки в CMS ещё не отражаются на нём автоматически.

## Перед публикацией основного домена

Нужно получить реальные фото и чертежи, подтвердить технические параметры и актуальные контакты по направлениям, настроить получение заявок, CRM и 1С, проверить страницы и редиректы, убрать запрет индексации на основном домене. Сводка по отсутствующим снимкам и характеристикам находится в `research/catalog-audit.csv`.
